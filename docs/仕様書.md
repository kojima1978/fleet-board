# FleetFlow 仕様書

社用車の駐車位置、予約、利用開始、返却、利用履歴を管理する社内向けWebアプリの仕様をまとめます。操作手順と運用手順の正本は[README.md](../README.md)、利用者向けの説明は画面の「使い方」（`/help`）です。この文書は、機能・データ・制約値を一か所で確認するためのものです。

- 対象バージョン：2026年11月時点の`main`
- 数値や制約は、各節に書いたソースファイルの定数が正です。食い違ったらコードを優先し、この文書を直します。

---

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 目的 | 社用車の「どこに停まっているか」「だれが使っているか」「いつ空くか」を、駐車場配置図とタイムラインで共有する |
| 利用者 | 社員（利用開始・予約・返却）、管理担当者（社員・車両・区画・案内の設定、データ保存） |
| 利用場所 | 社内LAN。入口の共用端末と、各自のPCから同じURLを開く |
| 本人確認 | 社員証（NFC）、社員QR、または一覧からの手動選択。ログインはしない |
| 読取機器 | NFC：Sony RC-S300／RC-S380、QR：DENSO QK30-U。各PCの「FleetFlow連携ソフト」（NFC Bridge）経由 |

### 1.1 設計の前提

- ログインのない共用端末向けの設計です。LANへ接続できる人は、業務データと設定を閲覧・変更できます。
- インターネットへは公開しません。
- 読取機器や連携ソフトが止まっても、社員・車両の手動選択で業務を続けられます。

## 2. 構成と利用環境

### 2.1 技術構成

| 層 | 採用技術 |
| --- | --- |
| 画面・API | Next.js 16（App Router）、React 19、Tailwind CSS v4、lucide-react |
| 入力検査 | zod |
| DB | PostgreSQL 17、Prisma 7（`prisma/schema.prisma`、番号付き移行SQL） |
| 実行環境 | Docker Compose（アプリ、DB、`db-backup`） |
| 読取連携 | NFC Bridge（Windows常駐、`127.0.0.1:17831`） |

### 2.2 環境

| 環境 | 用途 | 起動 |
| --- | --- | --- |
| 本番 | 業務利用 | `FleetFlow Production Start.cmd` |
| 開発 | 改修・検査 | `FleetFlow Start.cmd` |

- 本番と開発はDBを分けています。同時には起動できません。
- 公開ポートはTCP 3035です。初期状態では`127.0.0.1`だけに公開し、LAN公開は`FleetFlow LAN Setup.cmd`で行います。
- 動作に必要なもの：Windows 10／11、Docker Desktop、Git、Chrome または Edge。

### 2.3 運用用コマンド

| ファイル | 内容 |
| --- | --- |
| `FleetFlow Production Start.cmd` | 本番の起動（初回は本番設定を作成） |
| `FleetFlow Production Update.cmd` | 本番の更新。更新前バックアップ → 型検査 → ビルド → 移行 → ヘルスチェック → 動作確認の順に行い、失敗したら自動で元に戻す。`npm audit --audit-level=high`で High 以上が見つかれば中止 |
| `FleetFlow Production Status.cmd` | 稼働状態の表示 |
| `FleetFlow Production Health Check.cmd` | 「異常」「注意」の点検 |
| `FleetFlow Production Preflight.cmd` | 起動前の事前診断（公開アドレス、ネットワーク種別など） |
| `FleetFlow Production Stop.cmd` | 本番の停止 |
| `FleetFlow Production Diagnostics.cmd` | 障害情報をZIPへ保存（`.env.production`とDBパスワードは含まない） |
| `FleetFlow Production Autostart Setup.cmd` | サインイン時の自動起動の登録 |
| `FleetFlow Production Backup Setup.cmd` | NAS・USBなど外部への毎日の複製の設定 |
| `FleetFlow Production Migration Export.cmd`／`Import.cmd` | 新しいPCへの本番データ移行 |
| `FleetFlow LAN Setup.cmd` | LAN公開（公開IPの設定と、同じサブネットだけを許可するファイアウォール規則） |

### 3.1 画面の共通ルール

- 確定ボタンは下の欄の右に大きな青いボタンで置き、左に「キャンセル」を置きます。
- 元に戻せない操作（予約の取り消しなど）は画面のいちばん下に赤い文字で置き、確認してから実行します。
- 主な操作は大きなボタン、補助の操作はひと回り小さいボタンです。
- スマートフォンは主な利用対象にしません。PCの画面幅（目安1100px以上）で崩れないことを優先します。

## 4. 状態

### 4.1 画面に出す状態

| 表示 | 意味 |
| --- | --- |
| 予約 | 将来の利用予定。まだ出庫していない |
| 利用中 | 利用開始の手続きが済み、出庫している |
| 駐車中 | 区画に停まっている |
| 完了 | 返却の手続きが済んだ利用 |
| 整備中 | 故障で駐車場内にある。区画に置いたまま利用開始だけを止める |
| 車検で外出 | 車検・修理で駐車場にない。区画は空く |

### 4.2 DB上の状態

| 対象 | 値 |
| --- | --- |
| 車両 `VehicleStatus` | `AVAILABLE`、`RESERVED`、`IN_USE`、`MAINTENANCE` |
| 利用 `TripStatus` | `RESERVED`（予約）→ `IN_USE`（利用中）→ `COMPLETED`（完了）。予約は `CANCELLED`（取消）にもなる |
| 整備 `MaintenanceStatus` | `SCHEDULED`（予定）→ `ACTIVE`（実施中）→ `COMPLETED`（終了）。予定は `CANCELLED`（取消）にもなる |
| 整備の種類 `MaintenanceKind` | `ON_SITE`（故障・駐車場内）、`OFF_SITE`（車検・修理で外出） |

予約は、予約の登録だけでは車両の状態や駐車位置を変えません。

## 5. 端末の使い方と利用者

### 5.1 端末モード

利用者チップの左のバッジで選びます。選んだ内容はそのPCのブラウザーに保存します（`lib/device-mode.ts`）。

| モード | 利用者の扱い |
| --- | --- |
| 自動（初期値） | NFCまたはQRが読める状態なら共用端末、どちらも使えなければ各自のPCとして扱う |
| 共用端末 | 社員証・QRで確認した人は、利用開始・予約・返却を終えるか、操作がない時間が「自動解除まで」を過ぎると解除する |
| 各自のPC | 選んだ利用者を「この端末の利用者」として残す。自動解除とリセットはしない。連携ソフトの接続確認もしない |

### 5.2 端末ごとの設定

| 設定 | 内容 | 初期値 |
| --- | --- | --- |
| 自動解除まで | 共用端末で利用者を解除するまでの時間。1分・3分・5分 | 3分 |
| 音声・効果音 | 案内の音声とNFC読取音 | オン |
| 待機中の演出 | 駐車場画面で1時間操作がないと、道路に車が1台走る。以後1時間ごと。まれにパトカー・救急車・消防車 | オン |

### 5.3 共用端末の自動復帰

| 項目 | 値 | 定義 |
| --- | --- | --- |
| 入力画面のリセット | 操作がないまま10分 | `lib/use-kiosk-idle.ts` |
| 予告 | 30秒前 | `lib/use-kiosk-idle.ts` |
| 利用者の自動解除 | 1・3・5分（初期3分）。最後の30秒はチップが黄色 | `lib/device-mode.ts` |

入力中、未保存のフォーム、確認画面、保存中は復帰を保留します。各自のPCと印刷画面は自動で戻りません。

### 5.4 利用者の選び方

- 社員証（NFC）または社員QRを読むと、その社員を利用者にします。別の社員証を読むと切り替わります。
- 車両タグまたは車両QRを読むと、利用中の車は返却、それ以外は利用開始の画面を開きます。
- 手動検索は社員番号・氏名・部署で探せます。「E001」「001」と全角でも探せ、テンキーも使えます。
- 候補は20人ずつ表示します。候補が1人になっても自動では確定しません。
- 利用停止中の社員は候補に出ません。
- 未登録のカード・タグを読むと、画面下の通知にUIDを6秒表示します。
- NFC読取の待ち時間は15秒です（`NFC_SCAN_TIMEOUT_MS`）。

## 6. 機能仕様

### 6.1 利用開始（今すぐ利用）

1. 配置図で車両を選び、「今すぐ利用」を押す。
2. 社員証・社員QRを読むか、社員を手動で選ぶ。
3. 返却予定を選び、「この内容で利用開始」を押す。

- 利用時間は15分以上、7日（10,080分）以内です。
- 同じ社員が同時に2台を利用中にはできません。
- ほかの予約や整備予定と重なる時間は選べません。
- 予約した車は「今すぐ利用」から「予約した車両を利用開始」で開始します。
- 開始時点の社員名・社員番号・部署名・車両名・車両番号・ナンバーを利用記録へ保存します（後で登録情報を変えても、履歴の表示は変わりません）。

### 6.2 予約

| 種類 | 範囲 |
| --- | --- |
| 時間で予約 | 今日・明日・明後日から日付を選び、15分単位で開始と利用時間を決める |
| 1日利用 | 6:00〜22:00。開始が未来になる最初の日から7日後まで（`lib/all-day-reservation.ts`） |
| 日をまたいで利用 | 返却まで連続した利用。最大7日間 |

- 利用時間は15分以上、7日以内です。
- 同じ車両・同じ利用者の別の利用や予約、整備予定と重なる予約は保存できません。
- 予約時刻になっても自動では利用中になりません。利用開始の手続きが必要です。
- 開始予定から30分以内に開始されなかった予約は、自動で取り消して操作履歴へ「予約自動取消」として残します（`RESERVATION_GRACE_MINUTES = 30`）。
- 予約開始の30分前から、配置図の車両に紫の目印を付け、右側に「まもなく利用予定（30分以内）」を出します（`PARKING_RESERVATION_NOTICE_MINUTES = 30`）。開始時刻を過ぎると「開始待ち」になります。
- タイムラインの「予定一覧」は30日表示を初期値とし、7日・30日・90日を切り替えられます。選択期間に重なる利用予約・車検予定・車検中を日時順に表示します。
- 予定一覧の日付見出しは、日付の位置が揃うよう「11/5(木) 今日」の順で表示します。「今日」は当日の行だけに付けます。

#### 予約の変更と取り消し

- タイムラインの予約帯または「予定一覧」の利用予約から「予約を変更」を開きます。ドラッグ移動はできません。
- 「変更内容を確認」で変更前後を比べ、「この内容で予約を変更」で保存します。
- 開始は現在より後、利用時間は15分以上7日以内です。
- 取り消しは画面下の赤い「この予約を取り消す」から、確認してから行います。

### 6.3 延長

- 駐車場で利用中の車を選ぶか、タイムラインで利用中の帯を押すと、同じ「延長」「返却する」の画面が開きます。
- この画面には次の予約を出します。次の予約まで1時間を切ると、黄色で「次まで◯分」（重なっていれば「次の予約と重複」）を出します。
- 利用中の車は延長だけができます。短縮はしません（早く戻れば返却で空くため）。
- 選べる幅：30分、1時間、2時間、3時間、終日（その日の23:59まで）。
- 返却予定を過ぎた車は、今からの時間で延ばします。
- 開始から7日まで、次の予約や整備予定と重ならない範囲で延長できます。

### 6.4 返却

1. 配置図で返却先の空き区画を選ぶ（返却できる空き区画は緑に点滅）。
2. 車両タグ・車両QRを読むか、利用中の車を手動で選ぶ。
3. ガソリン残量を5段階（F・3/4・1/2・1/4・E）から選ぶ。前回の残量が選ばれた状態で開く。
4. 内容を確認して確定する。

- タイムラインで「返却する」を押すと、駐車場の画面へ移って1から始めます。
- 返却が済むと、右の「利用中」から返却先へ車が約1.2秒で走る演出を出します。
- 早く返却した場合は、タイムラインの帯を実際の返却時刻まで縮めます。
- 残量を選ばずに返却すると、前回の残量が残ります。

#### 返却の取り消し

| 項目 | 値 | 定義 |
| --- | --- | --- |
| 画面の「返却を取り消す」 | 返却後30秒だけ表示 | `UNDO_RETURN_SECONDS`（`components/fleet-dashboard.tsx`） |
| サーバーが受け付ける期限 | 返却から2分 | `undoReturn`（`app/api/dashboard/route.ts`） |

- 取り消すと利用中へ戻り、残量も返却前の値に戻します。
- 返却後に車両の位置・残量を直した場合や、その車・その利用者の状態が変わった場合は取り消せません。
- 共用端末では、別の人が社員証をかざした時点で取り消しの案内を消します。

### 6.5 利用開始時刻の訂正

- 「履歴 → 車両利用履歴 → その他：利用開始時刻を訂正」から行います。
- 訂正理由は必須で、200文字以内です。
- 未来の時刻、返却時刻以降、同じ車両・利用者の別の利用と重なる時刻にはできません。
- 変更前後・理由・操作した人を操作履歴に残します。予約日時・返却予定・駐車位置・状態は変えません。

### 6.6 駐車後の修正

配置図で駐車中の車を選ぶと、社員証なしで次の修正ができます。

| 操作 | 内容 | 操作履歴 |
| --- | --- | --- |
| 位置変更 | 空き区画を選ぶか、車をドラッグする | 駐車位置修正 |
| 位置未設定から置く | 配置図の右の「位置未設定」から区画へ置く | 駐車位置修正 |
| 残量変更 | 残量を選び直す | 残量修正（変更前と変更後） |

### 6.7 ガソリン残量と案内

残量は0〜4の整数で保存し、表示はE・1/4・1/2・3/4・Fです（`lib/fuel-level.ts`）。

#### 案内の表示方法

「表示なし」「メッセージ」「強調表示」「ポップ表示」の4種類から、残量ごとに選びます。

| 場面 | 初期状態 |
| --- | --- |
| 利用開始時 | 1/2：メッセージ、1/4・E：強調表示、F・3/4：表示なし |
| 返却時 | 1/4・E：ポップ表示、1/2以上：表示なし |

- 利用開始時に「ポップ表示」を選んだ残量では、案内を確かめるまで利用開始ボタンを押せません。
- 返却時のポップ表示は7秒で自動で閉じます。マウスを置いている間は止まり、音声が7秒より長ければ再生が終わるまで待ちます。
- 残量ごとの案内文は1〜500文字です。
- 音声はMP3・WAVで、1件2MBまでです（`FUEL_NOTICE_AUDIO_MAX_BYTES`）。

#### 給油時のお礼

- 出庫時より返却時の残量が増えたら給油と判断し、残量ごとの案内より先に「給油時のお礼」を出します。
- 出庫時の残量が分からない場合や、同じ残量の場合は給油と判断しません。
- お礼の文面は1〜300文字です。
- お礼は約4秒で閉じます（音声が長い場合は再生が終わるまで）。

#### 音声の再生

- 各自のPCはメッセージだけを出します。
- 共用端末は「音声・効果音」がオンで、音声が登録されていれば1回再生します。
- 駐車案内と重なったときは、ガソリン案内を優先します。
- 案内や音声に失敗しても、返却は止まりません。

### 6.8 駐車案内

「設定 → 案内設定 → 駐車案内」で、次の5つを個別にオン・オフします。

| 案内 | 初期状態 |
| --- | --- |
| 出庫を開始 | なし |
| 駐車区画を選択 | なし |
| 入庫内容を確認 | なし |
| 出庫できない | あり（サンプル音声） |
| 入庫できない | あり（サンプル音声） |

- 読み上げ文は1〜300文字です。音声はMP3・WAVで、1件2MBまでです。
- 音声ファイルがない項目は、端末の日本語読み上げで読み上げます。
- 手前の区画に車がある場合は、通常の案内の代わりに「出庫できない」「入庫できない」を1回だけ流します。
- 駐車案内、利用開始時、返却時、給油時のお礼は、それぞれ「初期設定に戻す」で戻せます。
- 初期のサンプル音声はVOICEVOX:ずんだもんです。

### 6.9 車検・故障（整備）

「設定 → 車両登録」の各車の「車検・故障」から登録します。

| 種類 | 車の場所 | 区画 |
| --- | --- | --- |
| 故障（駐車場内） | 区画にあるまま。画面の表示は「整備中」 | 置いたまま |
| 車検・修理で外出 | 駐車場にない。画面の表示は「車検で外出」 | 空ける（ほかの車を停められる） |

| 項目 | 値 | 定義 |
| --- | --- | --- |
| 予定を登録できる範囲 | 366日先まで | `MAINTENANCE_SCHEDULE_DAYS_AHEAD` |
| 1回の整備の最長期間 | 90日 | `MAINTENANCE_MAX_DAYS` |
| 備考 | 200文字以内 | `MAINTENANCE_NOTE_MAX` |
| 駐車場画面に予定を出す時期 | 開始予定日の2日前から | `UPCOMING_MAINTENANCE_DAYS_BEFORE` |
| 駐車場画面に出す予定の件数 | 最大3件 | `UPCOMING_MAINTENANCE_LIMIT` |

- 「今すぐ」は利用できる車だけ開始できます。故障をすぐ記録できるよう、既存の予約と重なっても開始できます。重なった予約は個別に調整します。
- 「予定を登録」すると、タイムラインに整備の帯が出ます。予約や延長は整備予定と重ねられません。
- 戻り予定が未定の間は、その車の予約を受け付けません。
- 予定は自動では始まりません。当日（または開始予定を過ぎた日）に、配置図で車を選んで「車検を開始」（故障は「整備を開始」）を押します。
- 車検中の車は右の「車検中」から、半日・1日・2日の延長ができます。
- タイムラインの帯のうち、車検中と予定の帯は押すと駐車場と同じ詳細を開きます。「車検を終了」「車検を開始」を押すと駐車場の画面へ移り、区画選び・開始の画面から始めます。済の帯と故障（駐車場内）の帯は押せません。
- 戻ったら「車検を終了」を押し、区画と残量を選んで「区画◯◯に停めて終了」で終えます。区画を選ばなければ位置未設定になります。
- 故障の車は「整備解除」で、今の区画のまま使えるようにします。
- 駐車場画面からの操作は「操作する人」を選び、その社員名を操作履歴に残します。設定画面からの操作は「設定画面」として残します。

### 6.10 社員

| 項目 | 仕様 |
| --- | --- |
| 社員番号 | 英字1文字＋数字3桁（例：E001）。小文字・全角は半角大文字にそろえる。DB制約でも強制 |
| 氏名 | 1〜50文字 |
| メールアドレス | 任意。254文字以内。重複不可 |
| 部署 | 利用中の部署から選ぶ |
| NFC UID | 任意。区切り文字を除いて正規化。社員・車両を通じて重複不可 |
| QR | 社員番号とは別の変更不能なトークン。紛失・誤送信時は再発行でき、旧QRはすぐ無効になる |
| 利用停止 | 利用開始の選択肢から外す。NFCの割り当ては外れ、履歴は残る。「利用再開」で戻せる |

- JSON取込は新規登録専用で、最大500件です。1件でも誤りがあれば全件を登録しません。未登録の部署名は自動で追加します。
- QRメール配信は、社用メールの登録がある社員へ一度に最大100人まで送れます。SMTPの設定が必要です。

### 6.11 部署

- 部署名は1〜50文字で、同じ名前は登録できません。
- 上下ボタンで並べた順に、社員画面の選択肢と絞り込みへ並びます。
- 有効な社員が所属する部署は利用停止できません。

### 6.12 車両

| 項目 | 仕様 |
| --- | --- |
| 車両番号 | 英字1文字＋数字3桁（例：C001）。DB制約でも強制 |
| 車両名 | 1〜50文字 |
| ナンバー | 1〜30文字。重複不可 |
| 表示色 | 12色（ホワイト・シルバー・グレー・ブラック・ネイビー・ブルー・レッド・オレンジ・イエロー・グリーン・ブラウン・ベージュ）＋「その他」で任意の色 |
| 装備 | ETC、ナビ、バックモニター、スタッドレスタイヤ装着 |
| 車種 | 普通車・軽自動車。軽は配置図で小さく表示し「軽」マークを付ける |
| ガソリンカード | 任意、40文字以内。カード番号は保存せず、見分けられる名前だけを登録する |
| 駐車区画 | 新規登録では必須。場所が決まらない車は仮置き区画を選ぶ。専用区画は選べない |
| NFC・QR・利用停止 | 社員と同じ |

- バックモニター付きの車は、配置図の車アイコンにカメラマークを付けます。
- スタッドレスタイヤ装着の車は、雪マークを付けます。11月〜4月は配置図の見出しにも意味を表示します。

### 6.13 駐車区画

| 項目 | 仕様 |
| --- | --- |
| 区画番号 | 1〜12文字、空白不可、全角は半角にそろえる、重複不可 |
| 表示・利用 | オン／オフ。オフの区画は配置図・駐車先・手前区画の判定から外す。駐車中はオフにできない |
| 推奨車種 | 指定なし・普通車用・軽自動車用。車種が異なる場合は確定前に注意するが、駐車は可能 |
| 表示名 | 「自動」（用途から決まる）か「任意」（10文字以内） |
| 手前の区画 | 中央の道路側にあって、そこに車があると出し入れできない区画。1区画につき最大20件 |
| 区画の位置と数 | 変更できない |

| 用途 | 内容 |
| --- | --- |
| 通常 | 社用車の通常の駐車位置 |
| 一時 | 通常の区画ではないが、一時的に返却できる（配置図では点線） |
| お客様用 | 停められるが、選ぶと注意を出して空いている通常区画をすすめる。返却時の点滅はしない |
| 専用 | 指定した1台だけが停められる |
| 仮置き | 実在しない区画。場所が決まらない車を一時的に置く（配置図では点線） |

- 手前の区画に車があると、出庫・入庫の場面で黄色の注意を出します。注意だけで、操作はそのまま続けられます。
- 推奨車種と異なる車を選ぶと、車種に合う空き区画を案内します。専用区画とは異なり、確認後は選択した区画へ駐車できます。
- 空き区画には、設定がある場合だけ「普通車用」または「軽自動車用」を表示します。この場合は重複する「返却先」を省きます。設定画面の配置図は「普」「軽」の略号を使い、指定なしは無表示とします。表示オフの区画でも設定内容を確認できます。既存区画と旧JSONバックアップの初期値は「指定なし」です。
- 空き区画の中央にはピンアイコンを出さず、「空き」と用途（返却先・お客様用・一時駐車可・専用車両名など）を文字で表示します。表示オフの区画は通常の配置図で枠・点線・影・操作領域を含めて描画せず、設定画面だけにグレーの破線と「非表示」ラベルで残します。
- 区画ごとの「初期設定に戻す」で、配置図上の位置を基準に本来の手前の区画へ戻せます。
- 区画番号を変えても、過去の履歴・返却先の記録は変更前の番号のまま残ります。

### 6.14 履歴

#### 車両利用履歴

- 車両を選ぶと、過去1か月の利用を表示します。「過去3か月」「期間指定」に切り替えられます。
- 利用者名・期間で絞り込めます。予約と取消は含みません。
- 返却時のガソリン残量を表示します。記録がなければ「未記録」、利用中は「—」です。
- 「CSV」で、最後に検索した条件に合う記録を最大10,000件書き出します。

#### 操作履歴

- 利用者・内容のキーワード、操作の種類、期間で絞り込めます。
- 「CSV」で、検索条件に合う履歴を最大10,000件書き出します。日時は日本時間（`2026/11/03 09:20`）です。
- 同じ画面で、アプリ・DB・NFC・バックアップの状態と、アプリ・DBのバージョンを確認できます。

### 6.15 データ保存・復元（JSON）

- 社員、部署、車両、駐車区画、NFC割当、QR識別子、利用予定、利用履歴、整備記録、案内設定と音声、操作履歴を1つのJSONへ書き出します。
- JSONには個人情報、NFC UID、QR識別子が含まれます。
- 復元は、ファイルを検査して件数を示したあと、確認欄に`RESTORE`と入力した場合だけ実行します。1つのトランザクションで全データを置き換え、途中で失敗したら元に戻します。
- 取り込めるファイルは50MBまでです（`JSON_BACKUP_MAX_BYTES`）。
- この機能は手動の退避と移行の補助です。自動DBバックアップ（7.3）とは別のものです。

### 6.16 NFC・QR連携

- ブラウザーは読取機器へ直接つながらないため、各PCで「FleetFlow連携ソフト」（NFC Bridge）を動かします。NFCとQRを1つのソフトで待ち受けます。
- セットアップ用のファイルは「設定 → NFC・QR」から`/api/scanner/setup`でダウンロードします。
- Windowsのサインイン時に自動で起動します。止まった場合は5秒ごとに検出して自動で再起動し、USBを抜き差ししても自動で再接続します。
- 状態は`http://127.0.0.1:17831/health`で確かめます。`readerConnected`（NFC）、`qrReaderConnected`（QR）が`true`なら接続済みです。
- 接続を許可する画面のURL（Origin）は完全一致で判定し、連携ソフトの起動時に読み込みます。サーバーのURLが変わったら再インストールします。

### 6.17 緊急時

障害でアプリが使えないときに備え、空の駐車場配置図と空のタイムラインをA4横で印刷できます。紙で運用し、復旧後に入力し直します。

## 7. 非機能仕様

### 7.1 画面の更新と同時操作

| 項目 | 仕様 |
| --- | --- |
| 自動更新 | 駐車場・タイムラインは5秒ごと、設定画面は30秒ごと。保存後と画面へ戻ったときは待たずに再取得する |
| 変更なしの応答 | ETagとサーバー内のスナップショットで304を返す。同時の取得は同じDB検索を共有する |
| 同時の変更 | 各表の`version`列で楽観的ロックを行い、先に変えられていたら「競合」として失敗させる |
| 二重送信 | 利用開始・返却などには一意の操作IDを付ける。同じ通信を再送しても二重に登録しない |
| 直列化 | 利用者・車両ごとにDBの勧告ロックを取り、同じ人・同じ車への同時操作を順に処理する |

### 7.2 データの保護

- 社員番号・車両番号の形式、日時の前後関係、状態と日時の組み合わせ、残量の範囲などはDBのCHECK制約でも守ります。
- 利用中の記録は、車両ごと・社員ごとに1件までに部分一意索引で制限します。
- 利用開始時点の写し（社員名・車両名など）は、トリガーで書き換えを防ぎます。
- DBの変更は`prisma/migrations`の番号付きSQLで管理し、`prisma migrate deploy`で適用します。`prisma db push`は使いません。適用済みのSQLは書き換えず、追加の移行で直します。
- 移行SQLを足したら、`npm run db:check-drift`で`schema.prisma`とのずれがないことを確かめます。

### 7.3 バックアップ

| 項目 | 仕様 |
| --- | --- |
| 自動バックアップ | `db-backup`コンテナーが起動時と24時間ごとに作成し、一時DBへ復元して検査する |
| 保存期間 | 30日を超えたものを削除する |
| 外部への複製 | `FleetFlow Production Backup Setup.cmd`でNAS・USB・同期フォルダーへ毎日複製。SHA-256で検証し、新しい30ファイルを残す |
| 保存場所 | 本番は`backups/production`、開発は`backups` |
| 実DBの復元 | ファイル名の指定と`RESTORE`の確認入力が必要 |

### 7.4 セキュリティ

- 設定と履歴はPINなしで開けます。LANへ接続できる人は設定の変更とデータの復元ができる前提です。復元だけは`RESTORE`の入力を求めます。
- 本番は非rootユーザー、読み取り専用のファイルシステム、Linux capabilityをすべて外した状態で動かします。
- DBのポートはWindowsへ公開しません。
- CSPなどのセキュリティヘッダーを付けます。
- 変更系のAPIは、画面のURLとAPIの接続先が同じか（Origin）を確かめます。信頼するリバースプロキシを置く場合だけ`FLEETFLOW_TRUST_PROXY=true`にします。
- LAN公開時のファイアウォール規則は、同じサブネットからのTCP 3035だけを許可します。プライベート／ドメインのネットワークだけで有効です。
- `.env.production`、DBデータ、バックアップ、診断ZIPはGitへ登録しません。

| 車両 | `createVehicle`、`updateVehicle`、`updateVehicleNfc`、`rotateVehicleQr`、`setVehicleActive`、`importVehicles` | 車両登録、車両情報修正、車両QR再発行、車両JSON取込 など |

| 区画 | `updateSpot` | 区画設定変更 |
| | `resetSpotFronts` | 手前区画初期化 |

このほか、開始予定から30分を過ぎた予約はサーバーが「予約自動取消」として取り消します。
