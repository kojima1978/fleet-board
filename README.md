# FleetFlow

FleetFlowは、社用車の駐車位置、予約、利用開始、返却、利用履歴を一元管理する社内向けWebアプリです。社員証・車両のNFCタグと、社員・車両QRを使った操作にも対応します。

## 最初に読むところ

- リポジトリ：[https://github.com/kojima1978/fleet-board](https://github.com/kojima1978/fleet-board)
- clone用URL：`https://github.com/kojima1978/fleet-board.git`（ブランチは`main`）

このプロジェクトはDockerで動かします。通常運用には**本番環境**、開発・動作確認には**開発環境**を使用してください。

| 用途 | 使用するファイル | データ |
| --- | --- | --- |
| 日常の業務運用 | `FleetFlow Production Start.cmd` | 本番DB |
| 本番へ最新版を反映 | `FleetFlow Production Update.cmd` | 本番DBを保持 |
| 開発・画面確認 | `FleetFlow Start.cmd` | 開発DB |

本番環境と開発環境は別のDBを使用します。同時には起動せず、起動用ファイルが反対側のコンテナーを自動停止します。

Docker Desktop上では用途を判別しやすいよう、常設コンテナーを`fleetflow-production-*`または`fleetflow-development-*`という固定名で表示します。1台のPCで複数のFleetFlow環境を同時起動する構成には対応していません。

## AIエージェントで操作する場合

Claude CodeなどのAIエージェントにこのREADMEを読ませると、cloneからDockerの起動、状態確認までを任せられます。AIエージェントは、この章の規則に従って操作してください。

### 環境の選び方

- 依頼に「本番」「業務で使う」「サーバー」とあれば本番環境を使います。「開発」「動作確認」「画面確認」とあれば開発環境を使います。判断できない場合は利用者に確認します。
- 本番と開発は同時に起動できず、起動用ファイルが反対側を自動停止します。`.env.production`があるPCで開発環境を起動する前には、本番が止まってよいか利用者に確認します。

### 実行方法

- コマンドはPowerShellで、プロジェクトフォルダー（`compose.yaml`がある場所）から実行します。Git Bashではコンテナー内のパスが書き換わるため使いません。
- 起動用cmdに`-NoUi`を付けると、ダイアログやブラウザーを開かずに結果を標準出力へ書きます。成否は終了コード（0が成功）で判断します。
- Docker Desktopが停止中なら起動用cmdが自動で起動します。Docker Desktop自体が入っていない場合は、インストールせずに利用者へ伝えます。

```powershell
# 初回だけ：取得
git clone https://github.com/kojima1978/fleet-board.git
cd fleet-board
```

| 目的 | コマンド |
| --- | --- |
| 本番を起動（初回は設定も作成） | `& '.\FleetFlow Production Start.cmd' -NoUi` |
| 本番の状態確認 | `& '.\FleetFlow Production Status.cmd' -NoUi` |
| 本番の詳細な健全性確認 | `& '.\FleetFlow Production Health Check.cmd' -NoUi` |
| 本番の起動前診断 | `& '.\FleetFlow Production Preflight.cmd' -NoUi` |
| 本番を停止 | `& '.\FleetFlow Production Stop.cmd' -NoUi` |
| 本番の障害情報を保存 | `& '.\FleetFlow Production Diagnostics.cmd' -NoUi` |
| 開発を起動 | `& '.\FleetFlow Start.cmd' -NoUi` |
| 開発の状態確認 | `& '.\FleetFlow Status.cmd' -NoUi` |
| 開発のログ確認 | `docker compose logs --tail 100 app` |
| 開発の検査 | 「開発時の検査」のコマンド（すべて`docker compose exec app …`でDocker内実行） |

起動後の確認は、サーバー自身から次を実行してHTTP 200が返ることで行います（本番・開発とも同じポート）。

開発環境は起動時に`package-lock.json`を確認し、pullなどで依存関係が変わった場合だけDocker内の`node_modules`を自動同期します。依存更新後に`Module not found`が出た場合も、`FleetFlow Start.cmd`または`docker compose restart app`で同期できます。

```powershell
(Invoke-WebRequest http://localhost:3035/api/health -UseBasicParsing).StatusCode
```

### 利用者の確認が必要な操作

次の操作は、内容を説明して利用者の明示的な了承を得てから実行します。

- 本番更新（`FleetFlow Production Update.cmd`）と、本番PCでの`git pull`（先に`git status`で未コミットの変更を確認）
- バックアップの復元と移行パッケージの取込。`RESTORE`の確認入力は利用者自身が行い、AIエージェントが代わりに入力しません。
- LAN公開（`FleetFlow LAN Setup.cmd`）。ファイアウォールを変更し、管理者権限の承認画面が出ます。
- サインイン時の自動起動の登録・解除（`FleetFlow Production Autostart Setup.cmd`）
- `.env.production`の編集・削除
- DBボリュームを消す操作（`docker compose down -v`、`docker volume rm`など）。バックアップが無い状態では実行しません。

### 秘密情報の扱い

- `.env.production`のDBパスワードなどを会話や作業記録へ書き写しません。
- `.env.production`、DBデータ、バックアップ、診断ZIPはGitへ登録しません（`.gitignore`済み）。

## 必要なもの

- Windows 10またはWindows 11
- Docker Desktop
- Git
- ChromeまたはEdge
- NFCを使う場合のみ：Sony RC-S300またはRC-S380、Sony NFCポートソフトウェア
- QRを使う場合のみ：DENSO QK30-U、Active USB-COMドライバー（QK30-UをUSB-COMモードで使用）

Docker Desktopは起動用ファイルから起動できます。初回はDocker Desktopのセットアップを完了してから進めてください。

## 新しいPCへcloneした後の起動

PowerShellを開き、保存したいフォルダーで次を実行します。

```powershell
cd C:\Users\ユーザー名\Desktop\apps
git clone https://github.com/kojima1978/fleet-board.git
cd fleet-board
& '.\FleetFlow Production Start.cmd'
```

初回起動では次の処理を自動実行します。

1. `.env.production`を作成
2. DBパスワードを自動生成
3. Dockerイメージと本番DBを準備
4. DBスキーマと駐車区画の初期データを登録
5. アプリを起動してブラウザーを開く

起動後のURLは[http://localhost:3035](http://localhost:3035)です。

> Gitに保存されるのはプログラムだけです。既存PCの社員・車両・予約・履歴などのDBデータと`.env.production`は、cloneだけでは新しいPCへ移りません。データ移行には「バックアップと復元」を使用してください。

## 既存フォルダーでpullした後の更新

本番データを使っているPCでは、単純な再起動ではなく、検査と自動復帰機能を備えた本番更新を使用します。

```powershell
cd C:\Users\ユーザー名\Desktop\apps\fleet-board
git status
git pull origin main
& '.\FleetFlow Production Update.cmd'
```

`git status`に自分で変更したファイルが表示された場合は、上書き事故を避けるため、pullする前に変更内容を確認してください。

本番更新は、更新前バックアップ、型検査、ビルド、DB移行、ヘルスチェック、主要操作テストを順番に実行します。途中で失敗した場合は本番切替を中止し、切替後の検査で失敗した場合は直前のアプリイメージへ自動復帰します。

更新後は次を実行して全体の状態を確認してください。

```powershell
& '.\FleetFlow Production Health Check.cmd'
```

## 日常の起動・停止・状態確認

エクスプローラーから次のファイルをダブルクリックできます。PowerShellでは、ファイル名に空白があるため`&`と引用符を付けます。

```powershell
# 起動
& '.\FleetFlow Production Start.cmd'

# 状態確認
& '.\FleetFlow Production Status.cmd'

# 詳細な健全性確認
& '.\FleetFlow Production Health Check.cmd'

# 起動前の設定・Docker・容量確認
& '.\FleetFlow Production Preflight.cmd'

# 停止（DBとバックアップは残ります）
& '.\FleetFlow Production Stop.cmd'

# Windowsへのサインイン時に自動起動する（解除は -Remove）
& '.\FleetFlow Production Autostart Setup.cmd'
```

サーバーPCでは`FleetFlow Production Autostart Setup.cmd`を一度実行しておくと、再起動後にサインインした時点で本番環境が自動起動します。LANの公開アドレスがPCへ割り当てられ、Docker Desktopの準備が終わるまで待ってから起動するため、ネットワークの準備前に起動して失敗することを防げます（公開アドレスが無いとDockerはポートを公開できず、アプリ全体が起動しません）。起動に失敗した場合だけ画面に表示し、経過は`nfc-bridge\fleetflow-start.log`に記録します。Docker Desktopはサインインしないと動かないため、再起動後は必ずサインインしてください（自動サインインも可）。同じPCで開発環境を使っている場合も、サインイン時には本番環境へ切り替わります。

本番の通常起動は、最後に検証済みのイメージを再利用します。ソースをpullしただけでは本番へ反映されません。変更を反映するときだけ`FleetFlow Production Update.cmd`を実行してください。起動と更新の前には、Docker構成、秘密情報、公開アドレス、ポート、ディスク空きを自動点検します。NFC未接続や容量低下などは注意表示に留め、設定欠落など安全に起動できない場合だけ停止します。

## 開発環境

開発環境も必ずDockerで動かします。

```powershell
# Docker、開発用アプリ、DB、NFC Bridgeを確認して起動
& '.\FleetFlow Start.cmd'

# 状態確認
& '.\FleetFlow Status.cmd'

# 起動するPCのLAN IPを自動検出して許可設定へ反映し、再ビルドして起動
& '.\FleetFlow Start.cmd' -Build
```

Windows用の`FleetFlow Start.cmd`は、通常起動・`-Build`での再ビルドともに、現在のLAN IPを自動取得してNext.jsの開発用Origin許可へ渡します。過去のIPを含むイメージを別PCへ持ち込んでも、起動したPCのIPでJavaScriptやHMRを読み込めます。許可先は実際に検出したプライベートIPv4と設定済みのIP・PC名だけで、ワイルドカードは使いません。

この処理はファイアウォール・公開先IP・`.env.production`を変更しません。LAN公開そのものは初回に`FleetFlow LAN Setup.cmd -Development`で設定してください。公開先IPが変わった場合もLAN設定の再実行が必要です。`docker compose up --build`を直接実行する場合、Windows側の自動検出処理は通らないため、`.env`の`FLEETFLOW_DEV_BIND_ADDRESS`へ現在の公開IPを設定してください。

Dockerコマンドを直接使う場合：

```powershell
docker compose up --build -d
docker compose ps
docker compose logs -f app
```

停止・再開：

```powershell
docker compose stop
docker compose start
```

コンテナーを作り直す場合：

```powershell
docker compose down
docker compose up --build -d
```

`docker compose down`ではDBボリュームは消えません。`docker compose down -v`は開発DBを全削除するため、バックアップなしでは実行しないでください。

開発用DockerはDBが空かどうかを自動判定し、開発・本番で共通の番号付きSQL移行を適用します。旧db push方式の既存DBは、実際のテーブル・カラム・索引を確認して移行履歴を登録し、未適用の変更だけ追加します。データの矛盾や途中の構成を検出した場合は停止し、自動で削除・補正しません。開発用のサンプルデータは初回だけ追加します。アプリは初期状態で`127.0.0.1`だけへ公開されます（他のPCから開く場合は「社内LANで本番公開する場合」の`-Development`を参照）。DBはDocker内のアプリから接続し、Windowsへポート公開しないため、他環境のPostgreSQLともポートが競合しません。

開発サーバーはTurbopackのファイルシステムキャッシュを無効にしています（`next.config.ts`の`turbopackFileSystemCacheForDev: false`）。Windowsのフォルダーをコンテナーへ共有する構成では、キャッシュの読み書きが`EIO`エラーでビルドを止めることがあるためです。初回表示は少し遅くなりますが、通常の自動更新には影響しません。

## 主な画面

| URL | 用途 |
| --- | --- |
| `/` | 駐車場配置図（右側に車両番号付きの利用中車両を常時表示）、利用開始、返却、ガソリン残量、駐車位置の修正 |
| `/timeline` | 車両タイムライン、予約、予定時間の変更 |
| `/operations` | 車両利用履歴の検索・操作履歴の検索とCSV書き出し |
| `/settings` | 車両登録（`/settings/vehicles`）へ移動 |
| `/settings/employees` | 社員登録、JSON取込、NFC UID登録、社員QRの表示・保存 |
| `/settings/departments` | 部署の追加・名前変更・利用停止・並び順の変更 |
| `/settings/vehicles` | 車両登録、JSON取込、NFC UID登録、車両QRの表示・保存 |
| `/settings/spots` | 駐車区画の番号・用途（通常・一時・お客様用・専用・仮置き）・表示名の変更 |
| `/settings/data` | 全データのJSON書き出し・一括復元 |
| `/settings/system` | アプリ、データベース、バックアップ、NFCリーダー、QRスキャナの状態確認 |
| `/settings/scanner` | NFC・QRの初回セットアップ、接続復旧、アンインストール、Sony公式ドライバー案内 |
| `/settings/emergency` | 障害時に使う空の配置図・タイムラインの印刷 |
| `/print/parking` | A4横の空の駐車場配置図 |
| `/print/timeline` | A4横の空のタイムライン |

### 状態の意味

| 表示 | 意味 |
| --- | --- |
| 予約 | 将来の利用予定。まだ出庫していない |
| 利用中 | 利用開始手続きが完了し、車両が出庫している |
| 駐車中 | 車両が駐車区画にあり、配置図で位置を確認できる |
| 完了 | 返却手続きが完了した利用履歴 |
| 整備中 | 故障で駐車場内にあり、利用開始だけを一時停止している |
| 車検で外出 | 車検・修理で駐車場にない。区画は空けるので、ほかの車を停められる。戻ったときに停める区画を選ぶ（選ばなければ位置未設定） |

駐車場・タイムラインは5秒ごと、管理設定は30秒ごとに更新されます。設定変更の保存後と、画面へ戻ったときは待たずに再取得します。変更がない確認はETagとサーバー内スナップショットで304応答にし、複数端末から同時に確認されても同じDB検索を共有します。同時操作は`version`列による楽観的ロックで競合を検出します。利用開始や返却などには一意の操作IDが付き、同じ通信が再送されても二重登録されません。

共用端末の駐車場・タイムライン画面では、10分間操作がないと社員選択と入力画面を解除し、駐車場画面へ戻ります。30秒前に警告され、操作すると継続できます。設定画面の編集中と、各自のPCには適用されません。

## 基本操作

### ボタンの並び

- どの画面も、確定のボタンは下の欄の右に大きな青いボタンで置き、左に「キャンセル」を置きます。
- 予約の取り消しなど元に戻せない操作は、画面のいちばん下に赤い文字で置き、確認してから実行します。
- 利用中の車は「返却する」と「延長」だけを置きます。延長は「30分」「1時間」「2時間」「3時間」「終日」（その日の23:59まで）の5つから選びます。時間のボタンは選ぶだけで、選んだボタンを青い枠で囲み、「変更後」に延長後の時刻と延ばす時間を出します。「延長する」を押すと確定します。もう一度同じボタンを押すと選択を外せます。
- 主な操作は同じ高さの大きなボタン、補助の操作はひと回り小さいボタンです。

### 利用開始

1. 駐車場配置図で利用する車両を選びます。
2. 社員証をNFCで読む、社員QRを読む、または社員を手動選択します。
3. 利用予定時間を選び、「この内容で利用開始」を押します。
4. 車両が「利用中」になり、タイムラインへ反映されます。

### 予約

1. 駐車図の車両をクリックし、「予約する」を押します（今から出庫する場合は別の「今すぐ利用」を押します）。タイムラインの左の車両名をクリックしても、その車の予約画面を開きます。
2. 予約画面で利用者を確認し、「時間で予約」「1日利用」「日をまたいで利用」から日時を指定して「この内容で予約」を押します。画面内で利用開始へ切り替える操作はありません。
3. 予約時刻になったら「今すぐ利用」から利用者を確認し、「予約した車両を利用開始」を押します。各自PCでは一覧選択、共用端末では社員証・社員QRを使用できます。

駐車図の車両詳細は、上段に大きな「今すぐ利用」「予約する」、下段に小さな「位置変更」「残量変更」を表示します。利用中の車両を選ぶと、車両情報の右に同じ大きさの「延長する」「返却する」、下段に「延長」の5つのボタンと「変更後」を表示します。タイムラインの右の「利用中」では、各車を開くと「延長」の5つのボタンと、その下に「変更後」「延長する」「返却する」を表示し、「返却する」から駐車場の画面へ移って返却先の区画を選びます。返却予定後の時刻を初期表示し、現在の利用・他の予約・整備予定と重なる予約は保存できません。予約の登録では現在の利用状態・駐車位置は変更しません。

「時間で予約」は今日・明日・明後日の日付ボタン（曜日付き）から選び、開始予定の左右の±15分ボタンと利用時間で調整します。利用時間は見出しに表示し、プリセットの下の「−15分／返却予定日時／＋15分」で調整できます。開始日時の重複表示はせず、今日を選んだ際は過去の時刻にならないよう次の15分単位へ補正します。「1日利用」は6:00〜22:00の予約です。開始が未来になる最初の日から、予約可能な7日後までの日付・曜日をすべてボタンで表示します。6:00以降は明日から表示し、日付入力は不要です。「日をまたいで利用」は返却まで連続した利用（最大7日間）で、別々の日の予約ではありません。

予約時刻になっても自動では利用中になりません。利用開始の手続きが必要です。開始予定から30分以内に開始されなかった予約は自動取消され、履歴へ記録されます。使わないことが分かった時点で手動取消もできます。

予約時間は、タイムラインの予約帯または予約一覧をクリックすると開く「予約を変更」で編集します。誤操作を防ぐため、タイムラインのドラッグ移動は廃止しました。開始・終了をまとめて指定でき、初期設定では開始日時の変更に合わせて終了も動かして利用時間を維持します。チェックを外すと開始・終了を個別に指定できます。「予約全体を移動」の15分・30分・60分ボタンは入力に反映するだけで、すぐには保存しません。「変更内容を確認」で変更前後を比べ、「この内容で予約を変更」で保存すると画面が閉じます。開始は現在より後、利用時間は15分以上7日以内とし、車両・利用者の別の利用や予約、整備予定との重複、古い版からの変更を拒否します。失敗時は元の予約日時を保持し、成功時は変更前後の日時を操作履歴に残します。予約の取り消しは画面下の赤い「この予約を取り消す」から、確認してから行います。

利用中の返却予定は延長だけできます。早く戻ったときは返却すればその時点で車が空くため、短縮はしません。タイムラインで利用中の帯を押しても画面は開きません。返却予定を過ぎた車は、見出しが「今から」に変わり、今からの時間で延ばします。開始から7日まで、次の予約や整備予定と重ならない範囲で延長できます。

実際の出庫時刻を訂正する場合は、「履歴 → その他：利用開始時刻を訂正」を使用します。履歴では車両名・利用者名で検索し、利用中・返却済みの記録から選べます。利用頻度が低いため通常は折りたたんで表示します。先にこの端末の利用者を選び、正しい開始日時と訂正理由（必須・200文字以内）を入力し、変更前後と理由を確認して保存してください。未来の時刻、実際の返却時刻以降、同じ車両・利用者の別の利用や予約と重なる訂正はできません。変更前後・理由・操作した利用者・訂正日時を操作履歴に記録します。予約日時・返却予定・返却時刻・駐車位置・利用状態は変更しません。

駐車場画面では、予約開始の30分前から車両に紫の「予約・開始時刻」の目印を付け、右側の「利用中」の下に「まもなく利用予定（30分以内）」を表示します。予約者・利用時間・現在の駐車区画を確認でき、予約内容を押すと変更・取消画面を開けます。開始時刻になると「開始待ち」へ切り替わります。利用開始は配置図でその車両を選び、「今すぐ利用」から行います（この欄には利用開始のボタンを出しません）。開始前の利用開始や、予約だけでの駐車位置・利用状態の自動変更は行いません。利用中の車両に次の予約がある場合は「現在利用中・次の予約あり」と表示します。利用開始・取消・予約終了・自動取消猶予の終了後は予約欄から外れます。時間の境界ではAPIのデータが変わらなくても表示を更新します。

### 返却

1. 駐車場配置図で返却先の空き区画を選びます。
2. 車両タグをNFCで読む、車両QRを読む、または利用中車両を手動選択します。
3. ガソリン残量を5段階（F・3/4・1/2・1/4・E）から選びます。前回の残量が選ばれた状態で開きます。
4. 内容を確認して返却を確定します。

返却先を選ぶあいだ、その車両を返却できる空き区画は枠が緑に点滅します（左から順に波のように点滅します。OSで「視差効果を減らす」などを設定していると点滅しません）。配置図の下に、返却できる空き区画の数を表示します。

返却が完了すると、右側の「利用中」から返却先区画まで車が約1.2秒かけて走る演出を表示します。演出中も画面操作を妨げず、OSでアニメーションを減らす設定にしている端末では表示しません。通信や登録に失敗した場合は演出せず、エラー内容を表示します。

早期返却ではタイムラインが実際の返却時刻まで短縮され、超過時は現在時刻まで延長されます。誤って返却した場合は、返却後30秒間だけ表示される「返却を取り消す」から利用中へ戻せます。ボタンに残り秒数を表示し、30秒たつと案内は消えます。共用端末では、別の人が社員証をかざした時点でも消えます。サーバーは返却から2分を過ぎた取り消しを受け付けません。取り消すと残量も返却前の値に戻ります。

### 利用者の選択とNFC・QRの常時待機

「各自のPC」の出庫・予約手続きは、利用者の手動選択で行います。社員証・社員QRの読み取り案内、読取待機、読取タイムアウトは出しません。「自動」で機器が利用できず各自PCと判定された場合も同じ表示にします。すでにこの端末の利用者を選択済みなら、その利用者で確認できます。「共用端末」は従来どおり読取を案内します。

画面右上の利用者チップに、いま操作している利用者を表示します。「×」で選択を解除します。利用者選択と出庫・予約の利用者確認は、共通の社員検索UIを使います。各自のPCでは社員番号・氏名（部署も検索可）の検索欄を表示し、「テンキー」で画面上の数字ボタンを開けます。共用端末は社員証・社員QRを通常の入口とし、「社員番号で探す（手動選択）」を押すとテンキーが開きます。機器が未接続でも手動検索を使えます。

社員番号は「E001」「001」、全角の「Ｅ００１」「００１」でも検索できます。テンキーではEを省略して数字だけ入力します。「1文字消す」「クリア」「テンキーを閉じる・氏名で探す」を用意しています。候補は社員番号・氏名・部署を表示し、候補が1人になっても自動確定しません。本人の名前をタップして選びます。候補は20人ずつ表示し、「さらに20人表示」で続きも確認できます。100人を超えても全員を検索対象とし、利用停止した社員は候補に表示しません。選択済みの利用者を使う動作と、共用端末での自動解除は従来どおりです。

利用者チップの左のバッジに、この端末を「共用端末」と「各自のPC」のどちらとして使っているかを表示します。バッジを押すと「自動」「共用端末」「各自のPC」から選べます。選んだ内容はそのPCのブラウザーに保存します。

| 使い方 | 利用者の扱い |
| --- | --- |
| 自動（初期値） | NFCまたはQRの連携ソフトが読み取り可能なら共用端末、どちらも使えなければ各自のPCとして扱う |
| 共用端末 | 社員証で確認した人は、利用開始・予約・返却を終えるか、操作が3分ないと破棄する。10分操作がないと入力画面もリセットする |
| 各自のPC | 選んだ利用者を「この端末の利用者」として残す。自動解除とリセットはしない |

入口の端末でNFC Bridgeが止まっても共用端末のまま動かすには、「共用端末」を選んでおきます。共用端末から外すときは、前の人の名前が残るようになるため確認を出します。共用端末にすると、保存していた「この端末の利用者」は消えます。

同じメニューで、この端末だけの次の設定もできます。

- 自動解除まで：共用端末のときだけ表示します。1分・3分・5分から選びます（初期値は3分）。
- 共用端末のタイムライン・設定・履歴では、同じ時間操作がないと利用者選択を解除して駐車場へ戻ります。30秒前に予告し、画面操作・スクロール・社員証の読取・「操作を続ける」で延長します。入力中・未保存のフォーム・確認画面・保存中は復帰を保留し、保護が終わってから数え直します。各自のPCと印刷画面は自動復帰しません。
- 音声・効果音：返却時の給油音声案内とNFC読取音のオン・オフです（初期値はオン）。
- 待機中の演出：駐車場画面で1時間操作がないと、配置図の道路に車が1台走ります。そのまま操作がなければ、1時間ごとにまた1台走ります（初期値はオン）。10回に1回くらいはパトカー、ごくまれに救急車や消防車になり、赤色灯を点滅させながら少し速く走ります（音は鳴りません）。車は飾りで操作の邪魔をせず、画面を触る・マウスを動かす・キーを押す・NFCをかざすとすぐ消えます。OSで「視覚効果（アニメーション）を減らす」設定にしている端末では走りません。

NFCまたはQRスキャナが使えるPCでは、利用者を選んでいないとき、利用者チップが緑の「社員証・QR／選ぶ」になります。駐車場・タイムライン画面を開いていれば、ボタンを押さずにそのまま読み取れます。チップを押すと一覧から選べます。

- 社員証または社員QRを読むと、その社員を利用者として認証します。別の社員証・QRを読むと利用者が切り替わります。
- 車両タグまたは車両QRを読むと、利用中の車両は返却、それ以外は利用開始の画面を開きます。駐車場画面では、返却は配置図で返却先を選ぶところから始まり、空き区画が点滅します（タイムライン画面では返却画面を開きます）。
- 登録されていないカード・タグは、画面下の通知にUIDを表示します。NFCの通知は6秒で消えます（ほかのエラー通知は「×」で閉じるまで残ります）。
- 読み取ると短い効果音が鳴ります。読み取れた・認証できたときは高い音、未登録や読み取れないときは低い音です。ブラウザーの自動再生制限により、起動後に画面を一度も触っていないと鳴らないことがあります。
- 共用端末では、社員証での確認を利用開始・予約・返却を終えると破棄します。次の人は自分の社員証をかざしてから操作します。
- 共用端末で確認した利用者は、操作が3分（「自動解除まで」で変更可）ないと自動で解除します。利用者チップに残り時間を表示し、最後の30秒は黄色に変わります。画面を触るか社員証をかざし直すと、最初から数え直します。
- 配置図とタイムラインの「利用中」には、車両を見分けやすいよう車両番号を車両名の前に表示します。利用者を選んでいるときは、その人の車両を一番上に青い線と「あなたの利用」付きで表示します。
- リーダーが外れているとき、または共用端末でNFC Bridgeが止まっているときは、ヘッダーの「正常｜NFC」ボタンが黄色になり「NFC未接続」「NFC停止中」と表示します。押すと「再接続」、対処方法、手動読取を利用できます。「再接続」は表示を更新するだけではなく、BridgeとNFC・QR機器の接続を実際に作り直します。すべて正常なときは表示しません。
- 利用開始・返却などの画面を開いている間と設定画面では、画面全体の常時待機を止めます。開いている入力画面または設定の読取操作だけが受け取るためです。

NFC Bridgeがない場合は、NFCの表示を出さず、利用者チップから手動で選びます。各自のPCでは、選んだ利用者を「この端末の利用者」としてブラウザーに保存し、閉じて開き直しても残します。利用開始の画面で別の人を選んでも、この端末の利用者は変わりません。変えるときは利用者チップから選び直し、「×」で解除します。

端末設定で「各自のPC」を明示的に選ぶと、NFC・QR連携ソフトの常時接続確認を停止します。未導入のPCでも`127.0.0.1:17831`への定期的な接続エラーは出ません。「自動」は機器の検出のため接続確認を行います。「共用端末」も従来どおり接続を監視します。設定画面で明示的にNFC登録・確認を開始した場合は、「各自のPC」でも読み取りを試みます。

### ガソリン残量

- 残量はおおよそで構いません。選ばずに返却した場合は、前回の残量がそのまま残ります。
- 今すぐ利用する車両の残量が1/2以下の場合は、「今すぐ利用」を押して詳細入力画面を開いた時点で給油案内を短く強調します。配置図で車両を選んだだけでは表示しません。NFC・QRから直接利用開始画面を開いた場合も同じです。将来の予約登録では、利用時点の残量が未確定のため表示しません。
- 返却時に選んだ残量が1/4以下（1/4・E）の場合だけ、「ガソリン残量が1/2未満です」と次回からの給油協力を案内し、利用開始時と同じく表示直後に短く強調します。同時に端末設定の「音声・効果音」がオンなら音声を1回再生します。1/2では表示・再生しません。案内や音声の再生失敗によって返却操作が止まることはありません。
- 配置図の駐車中の車は青い枠で表示し、残量に応じて区画が青く塗られ、「残量 1/2」のように表示されます。1/4以下は黄色で表示されます。
- 返却時の残量は操作履歴（CSVも含む）に「区画14へ返却（残量 1/2）」のように記録されます。

### 駐車後の修正

配置図で駐車中の車をタップすると、詳細欄から次の修正ができます。社員証は不要です。

- 「位置変更」：移動できる空き区画が緑の点線で示されます。移動先をタップするか、車をその区画へドラッグします。操作履歴に「駐車位置修正」として残ります。やめるときは「やめる」を押します。
- 「位置未設定」：駐車位置が決まっていない利用可能な車両は、配置図の右に「位置未設定」として表示されます。車をタップして置く区画をタップするか、空き区画へドラッグします。長い車名は2行まで表示します。位置未設定のままでも、行の右の再生ボタン（利用開始）で使い始められます。画面上部の「駐車位置未確定」の案内もこの欄を示します。
- 「残量変更」：ガソリン残量を選び直します。操作履歴に「残量修正」として、変更前と変更後の残量（例：「フリードの残量を1/4から1/2へ修正」）が残ります。

車両登録時には残量を入力しません。残量が未登録の車も、駐車区画へ配置した後に「残量変更」から最初の値を登録できます。返却の直後に位置や残量を修正すると、その返却は取り消せなくなります。

## 社員・車両データ

- 社員は「設定 → 社員」、車両は「設定 → 車両」から登録します。
- 「JSON取込」で最大500件を一括登録できます。「ひな形を保存」で正しい形式を取得できます。
- JSON取込は新規登録専用です。重複や不正な行が1件でもある場合は全件を登録しません。
- NFC UIDは省略でき、取込後に編集画面から追加できます。
- UIDは区切り文字の有無にかかわらず正規化されます。
- 同じUIDを複数の社員・車両へ同時に割り当てることはできません。
- 社員・車両には、画面に表示する番号とは別に変更不能のQR識別子を持たせます。社員番号・車両番号を変更または将来再利用しても、古いQRが別の社員・車両へ移ることはありません。
- 一覧の「QR」から印刷用SVGを表示・保存できます。QRは新規登録時と旧データ移行時に自動発行し、通常の編集では変わりません。
- 社員には社用メールアドレスを任意登録できます。一覧の「QRメール配信」から最大100人を選んで一括送信でき、各社員の「QR」から個別送信もできます。送信の成否は操作履歴に残ります。
- 社員一覧は広い画面でメールアドレスを独立列に表示し、狭い画面では氏名の下へ表示します。未登録者には「メール未登録」を表示し、メール登録状況で絞り込めます。「QRメール」ボタンには送信可能人数を表示します。
- QRを紛失・誤送信した場合は、社員のQR画面で「紛失・誤送信のため再発行」を選びます。再発行すると旧QRは直ちに無効になり、新しいQRだけが使えます。
- 社員番号と車両番号は英字1文字と数字3桁だけを登録できます（例：社員E001、車両C001）。入力欄では、それ以外の文字は入力できません。小文字や全角で入力しても半角の大文字にそろえます。JSON取込も同じ形式で、DBの制約でもこの形式以外は保存できません。
  - 桁がそろうため、一覧と選択肢は番号の昇順に並びます。
  - 以前の番号は、更新時にすべて置き換えます。C01・e7のような番号は3桁へ埋め（C001、E007）、変換後の番号がすでにある場合や変換できない番号は、同じ英字（英字がなければ社員E・車両C）の空いている最小の番号にします。古いJSONバックアップを復元したときも同じ規則で置き換えます。
  - 同じ更新で、どの社員・車両にも使われていない番号を消し、初期データの仮のNFC UID（NFC-C02など）を割り当て先の番号に合わせます（NFC-C002）。実際のNFCタグのUIDは変えません。
- 社員番号と車両番号は将来再利用できますが、同じ番号を同時に有効化することはできません。
- 社員番号と車両番号は編集画面から変更できます。過去の利用履歴も新しい番号で表示されます。変更前の番号は、ほかに使う社員・車両がなければ残しません。
- 入替時は過去履歴を保つため、旧データの利用を停止してから新データを登録します。
- 退職・異動・廃車などで使わなくなった社員・車両は、編集画面の「利用停止」で利用開始の選択肢から外します。NFCの割り当ては解除され、履歴は残ります。一覧は初期状態で有効なものだけを表示し、停止中のものは「利用停止中」で絞り込んで「利用再開」できます。
- 部署は「設定 → 部署」で管理します。社員の登録・編集では、ここで追加した利用中の部署から選びます。
  - 同じ名前の部署は登録できません。名前を変更すると、所属する社員の表示もすべて変わります。
  - 上下ボタンで並べた順に、社員画面の部署の選択肢と絞り込みへ並びます。
  - 名前の変更と利用停止は、各部署の「編集」から行います。有効な社員が所属する部署は利用停止できません。先に社員の部署を変更します。停止中の部署は社員の選択肢に出ず、一覧の「利用再開」で戻せます。
  - JSON取込で未登録の部署名を指定すると、その部署を自動で追加します。停止中の部署名を指定した場合は利用を再開します。
- 車両にはETC・ナビの有無と、現在スタッドレスタイヤを装着しているかを登録できます。
- スタッドレスタイヤ装着車は、駐車区画内の車アイコン右上に小さな雪マークを表示します。11月から4月の冬季は配置図の見出しにも「雪マーク：スタッドレスタイヤ」と表示し、マークの意味を案内します。
- 車両には軽自動車かどうかも登録できます。軽自動車は、駐車区画内の車アイコンを普通車より少し小さく表示し、右下に黄色の「軽」マークを付けます。車両一覧にも「軽」と表示します。JSON取込では `isKei` に true または false を指定します。
- 車両ごとに使うガソリンカードを登録できます（任意、40文字以内）。カード番号は入力せず、「出光 末尾1234」のように会社名と末尾4桁など見分けられる名前だけを登録します。車両一覧の「ガソリンカード」列に表示し、検索欄でも探せます。JSON取込では `fuelCard` に文字列で指定し、省略すると未登録になります。JSONバックアップにも含みます。
- 車両の新規登録時に駐車区画を選択すると、登録と同時に駐車場配置図へ表示されます。新規登録では駐車区画の選択が必須です。場所が決まっていない新車は仮置き区画を選びます。仮置き区画がすべて埋まっていたら選べないため、仮置きの車を実際の区画へ移動してから登録します。利用停止から再開した車両も空いている仮置き区画に置き、空きがなければ位置未設定で再開します。JSON取込で区画を選ばなかった車両は、配置図の「位置未設定」から空き区画へ置けます。車両一覧の「状態・駐車位置」列は表示用で、位置未設定の車両には「配置図で置く」が出ます。JSON取込の確認画面では、車両ごとに駐車区画を選ぶか「空き区画を順に割り当て」でまとめて割り当てられます。選ばなかった車両は位置未設定になり、その台数を確認画面と完了時の案内に表示します。同じ区画の重複や、使用中・無効・専用区画への割当はサーバー側でも止め、1台でも失敗したら取込全体を登録しません。区画の変更は配置図の「位置変更」で行います。使用中・無効な区画と専用区画の制限はサーバー側でも確認します。新規登録の車両は専用区画を選べません。
- 「設定 → 駐車区画」で配置図の区画をタップし（一覧から選ぶこともできます）、区画番号・用途・表示名を変更できます。変更は配置図・返却先の選択・印刷に反映されます。
  - 区画番号は12文字以内で、空白は使えません。全角の数字・英字は半角にそろえます。ほかの区画と同じ番号にはできません。番号を変えるときは、保存前に確認画面を出します。
  - 表示名は配置図で番号の横に出す名前です（10文字以内、任意）。空欄なら用途から自動で決めます（例：専用なら「サクラ専用」）。用途や専用車両を変えると、表示名は空欄に戻ります。入力欄の下の候補ボタンから選ぶこともできます。表示名を変えた区画には、設定画面の配置図でペンの印が付きます。
  - 過去の利用履歴・返却先の記録は、変更前の番号のまま残ります。
  - 区画の位置と数は変更できません。起動時の初期設定は、設定画面で変えた番号・用途・表示名を上書きしません。
  - 通常：社用車の通常の駐車位置
  - 一時：通常区画ではないが、一時的な返却先として使える（配置図では点線）
  - お客様用：お客様用。社用車も止められるが、できるだけ止めない。返却・戻った・移動・位置未設定から置く・車両登録でこの区画を選ぶと、黄色の注意と空いている通常区画を出す。返却では「別の区画を選ぶ」で選び直せる。移動・置くときは「このまま止める」を押すまで動かさない。返却先を選ぶときの点滅はお客様用の区画では止める
  - 専用：指定した1台だけが駐車・返却できる。別の車が駐車中の区画は、先に移動しないと専用にできません
  - 仮置き：実在しない区画。駐車場所を確定できない場合だけ使う（配置図では点線）
  - 変更は操作履歴に「区画設定変更」として残ります。
- 社員・車両の通常登録・編集でもNFC UIDは任意です。NFC未登録のまま手動選択で利用できます。未登録時は「NFC登録」、登録済みなら「NFC変更」と表示します。登録済みのUIDを変更・解除して保存するときは、現在と変更後を確認してから確定します。DB更新が成功した時点で旧カード・タグの割り当てを自動解除します。外したカード・タグは、利用停止から再開しても戻りません。まだカード・タグを配っていない社員・車両は、一覧の絞り込みで「NFC未登録」を選ぶと確認できます。
- 手元のカード・タグがだれのものか分からないときは、社員登録・車両登録の一覧上部にある「NFCを確認」を押し、読み取るかUIDを入力します。割り当て先の社員・車両（利用停止中で、再開すると戻るものを含む）を表示し、そこから編集画面を開けます。どこにも割り当てていなければ、その旨を表示します。
- 一時的に使わない車両は「設定 → 車両登録」の「整備」から登録します。種類は2つです。
  - 故障（駐車場内）：車は区画にあるまま、利用だけを止めます。
  - 車検・修理で外出：車は駐車場にありません。区画は空けるので、その間ほかの車を停められます。駐車場画面の右の「まもなく利用予定」の下に「車検」として、利用中の車両と同じ形で表示されます。
  - 戻り予定と備考は任意です。戻り予定より後の予約は受け付け、戻り予定が未定の間は予約できません。
  - 「今すぐ」は利用可能な車両だけ開始できます。故障をすぐ記録できるよう、既存の予約とは重なっても開始できるため、重なった予約は個別に調整してください。
  - 「予定を登録」すると、タイムラインに整備の帯が出ます。予約や延長と整備予定は重ねられません。予定は前倒しで開始・取消できます。取消は確認してから行います。日程がずれたときは、登録済みの予定の「変更」から開始予定・戻り予定・備考を直せます。開始予定を過ぎても、実際に出るときに「開始」を押せば、その時刻から外出になります。整備予定がある車両は、予定を取り消してから利用停止できます。
  - 予定は開始予定日の前日から、駐車場画面の右の「車検」の下に「車検・整備の予定」として最大3件表示します。開始予定を過ぎても開始していない予定も残ります。行の形は「まもなく利用予定」と同じで、今の区画・戻り予定と「出庫待ち」（今日の予定）か「出庫予定」（明日の予定）を出します。タップすると車検・故障の画面が開きます。
  - 予定は予約を止めるためのもので、自動では始まりません。実際に出庫するときは駐車場画面から操作します。今日（または開始予定を過ぎた）の予定は、配置図の区画に「車検 10:00」の札が付きます（枠は黄色。予約の札がある区画は予約を優先）。配置図で車両を選ぶと「出庫」（故障は「整備開始」）ボタンが出ます。右の「車検・整備の予定」には出庫のボタンを出しません。押すと出庫する人と戻り予定を確認してから外出にします。利用中の車両には出ません。
  - 駐車場画面から出す・戻すときは「操作する人」を選び、操作履歴にその社員の名前を残します（最初は画面上部で選んでいる社員）。設定画面からの操作は「設定画面」として残ります。
  - 戻ったら、配置図で車両を選ぶか右の「車検」の車をタップします（設定画面の「戻す・解除」でも可）。車検・修理で外出していた車は、空いている区画から停める区画を選びます。右の一覧から空き区画へドラッグすると、その区画を選んだ状態で開きます。選ばなければ位置未設定になり、あとで配置図から置けます。故障（駐車場内）の車は、指定がなければ今の区画のまま使えるようになります。
  - 整備記録はJSONバックアップに含まれます。

### 社員QRメール配信

メール配信を使う場合は、`.env`（本番は`.env.production`）へ社内メールサーバーのSMTP情報を設定してからDockerを再起動します。

```dotenv
SMTP_HOST=smtp.example.jp
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=fleetflow@example.jp
SMTP_PASSWORD=ここにパスワード
SMTP_FROM=FleetFlow <fleetflow@example.jp>
```

- 465番ポートの暗号化接続を使う場合は`SMTP_SECURE=true`にします。587番ポートのSTARTTLSは通常`false`です。実際の値はメール管理者へ確認してください。
- SMTPパスワードをGitへ登録しないでください。`.env`と`.env.production`はGitの管理対象外です。
- 配信メールには社員ごとのQR画像が付きます。転送・スクリーンショットでも利用できるため、紛失や誤送信時は必ずQRを再発行してください。
- LINEへの直接配信は未実装です。個人LINEとの連携にはLINE公式アカウント、本人とのアカウント連携、HTTPSのWebhook運用が必要になるため、まず社用メールで運用します。

## 全データのJSON保存・復元

「設定 → データ保存・復元」を開くと、社員・車両・駐車区画・NFC割当・QR識別子・利用予定・利用履歴・操作履歴を1つのJSONファイルへ書き出せます。JSONには個人情報、NFC UID、QR識別子が含まれるため、安全な場所へ保存してください。

復元する場合は、FleetFlowが書き出したJSONファイルを画面へドラッグ＆ドロップします。形式、重複、データ間の参照関係を検査した後、確認欄へ`RESTORE`と入力すると現在の全データを置き換えます。復元処理は1つのDBトランザクションで行われるため、途中で失敗した場合は変更前の状態へ戻ります。

このJSON機能は日常的な手動退避やデータ移行を補助するものです。自動DBバックアップは履歴、検証状態、障害復旧手順を含むため、引き続き有効にして併用してください。

## NFC・QR連携（RC-S300／RC-S380、DENSO QK30-U）

ブラウザーはPaSoRiやUSB-COMへ直接通信しないため、各利用PCでWindows用の「FleetFlow連携ソフト」を動かします。NFC Tools KBCは不要です。1つの連携ソフトでNFCとQRを同時に待ち受けます。

### 利用端末の初回セットアップ

「設定 → NFC・QR 接続ガイド」に、利用者向けの手順と接続状態を表示します。NFC・QRを使用する管理者PCまたは共通端末ごとに、次の順で1回だけ実施します。

1. NFCを使う場合は、[Sony公式のNFCポートソフトウェア](https://www.sony.co.jp/Products/felica/consumer/support/download/nfcportsoftware.html)をインストールします。対象はRC-S300／RC-S380で、Windowsの管理者権限が必要です。QRスキャナだけを使う端末では不要です。
2. NFCリーダーまたはQRスキャナをUSBへ接続します。NFCリーダーが認識されない場合はUSBハブを避け、PCへ直接接続します。
3. 接続ガイドの「セットアップツールをダウンロード」からexeを入手して実行します。FleetFlow Bridge、自動起動、復旧機能が現在のWindowsユーザーへ登録されます。
4. 接続ガイドへ戻り、「この端末の接続状態・復旧」でNFCリーダーとQRスキャナの状態を確認します。

SonyドライバーとFleetFlowセットアップの順番が逆でも問題ありません。両方を導入した後にUSBを挿し直し、必要に応じて画面の「NFC・QRを再接続」を実行します。Sonyドライバーのダウンロード・インストールはFleetFlowから自動実行せず、公式サイトで利用者またはPC管理者が行います。

SonyのNFCポートソフトウェアを導入してリーダーを接続した後は、Windowsの`FleetFlow Start.cmd`または`FleetFlow Production Start.cmd`からも初回準備ができます。RC-S300／RC-S380・PaSoRi・QK30を検出し、連携ソフトが未導入なら不足している実行ファイルをDockerでビルドして導入・起動します（初回は数分かかる場合があります）。起動時のFleetFlow URLを許可Originへ追加し、既存のQR設定は保持します。導入済みの場合は再ビルドせず、インストール先から起動します。ドライバーおよびWindowsログイン時の自動起動設定は変更しません。機器のない未導入PCでは初回準備を行いません。

別の利用PCでは、「設定 → NFC・QR 接続ガイド」を開いて「セットアップツールをダウンロード」を押し、ダウンロードしたexeを実行してください。展開操作、Docker、.NETの別途導入やURL・コマンドの入力は不要です。導入後は元の画面に戻ると自動で接続確認します。セットアップは現在のユーザー専用で管理者権限は不要です。Windowsログイン時のBridge監視を同じユーザーへ自動登録し、既存のQR設定・許可Originを保持したまま、開いていたFleetFlowのOriginを追加します。複数のFleetFlowを使う場合は、それぞれの画面からセットアップを実行します。同じツールを再実行すると、既存設定を保持したままBridgeを修復・再起動できます。

初回セットアップは一般利用者の日常操作ではなく、FleetFlowの導入担当者またはPC管理者が、USB読取機器を使うPCごとに1回実施します。Sony／DENSOドライバーの導入に管理者権限が必要な場合は、先にPC管理者が対応してください。セットアップ後の日常利用者はBridgeやDockerを操作せず、社員証・車両タグ・QRを読み取るだけです。PC交換時やUSB機器を別PCへ移すときは、新しいPCで初回セットアップを実行します。

接続先をファイル名に含めるため、ダウンロードしたexeの名前は変更しないでください。Windowsによる同名ファイルの「(1)」などの付加は許容します。バイナリはサーバーのDockerイメージをビルドするときに自動生成・同梱され、`/api/scanner/setup`から配布します。既存イメージには入っていないため、管理者による再ビルドが必要です。署名されていないexeのため、Windowsや社内ポリシーで警告・実行制限が出る場合があります。保護機能を無効化せず管理者へ相談してください。Windows x64専用です。Sonyドライバーは同梱・自動インストールしません。

プロジェクト一式を使う上記のWindows起動ファイル経由の準備にはDockerが必要です。DockerでBridgeをビルドした後、管理者は`nfc-bridge\FleetFlow NFC-QR Install.cmd`をダブルクリックして導入できます。詳細なオプションが必要な場合だけ、下記の`install.ps1`を直接実行します。通常の利用PCでは、FleetFlow画面から初回セットアップexeをダウンロードする方法を使います。

```powershell
docker compose --profile tools run --rm nfc-bridge-build
powershell -ExecutionPolicy Bypass -File .\nfc-bridge\install.ps1
```

QK30-Uも使う場合は、[DENSO WAVEのQK30ダウンロードページ](https://www.denso-wave.com/ja/adcd/product/scanner/qk30/dl/)からActive USB-COMドライバーを入れ、Windowsの「デバイス マネージャー → ポート（COMとLPT）」でQK30-UのCOM番号を確認します。次の`COM3`を実際の番号に置き換えてインストールしてください。QK30-UはUSB-COMモード、読取データの終端はCRまたはCR/LFにします。

```powershell
docker compose --profile tools run --rm nfc-bridge-build
powershell -ExecutionPolicy Bypass -File .\nfc-bridge\install.ps1 -QrComPort COM3
```

QK30-UがWindowsでDENSOのCOMポートとして1台だけ認識されていれば、`-QrComPort`を省略してもインストーラーが自動検出します。検出できない場合は明示してください。NFCだけを使うPCでは省略したままで構いません。QRだけを使うPCでも同じ連携ソフトを使用でき、PaSoRiは不要です。

`install.ps1`または画面からダウンロードした初回セットアップで導入すると、Windowsログイン時に監視用ランチャーが自動起動します。一般利用者がBridgeを毎回起動する必要はありません。連携ソフトが停止した場合は5秒ごとに検出して自動再起動し、WindowsやUSBの準備が遅い場合も再試行します。RC-S300／RC-S380やQK30-UをUSBから抜いた場合も待機を続け、挿し直すと通常は数秒以内に自動再接続するため、FleetFlowや連携ソフトの再起動は不要です。QK30-UがWindowsへ戻ってもシリアル接続だけが復旧しない場合は、機器が存在する状態での連続失敗を検出してBridgeだけを自動再起動します。NFCはPC/SCのリーダー一覧を再取得し、QRはQK30-UのUSB識別子を再検索するため、USBハブや差込口を変えてQRのCOM番号が変わっても自動追従します。QK30-Uが複数台ある場合だけ、使用するCOMポートを明示します。接続状態は画面右上へ簡潔に表示し、詳細確認と手動再接続は「設定 → NFC・QR 接続ガイド」で行います。

NFC・QRを使用する管理者PCおよび共通端末だけで初回セットアップを実行します。デスクトップとスタートメニューへショートカットは作成しません。通常は自動起動に任せ、USBの挿し直しで復旧しない場合は「設定 → NFC・QR 接続ガイド」を開きます。最初に画面の「NFC・QRを再接続」を押し、Bridge自体へ接続できない場合は同じ画面から「セットアップ・修復ツール」をダウンロードして実行します。このツールはPCやユーザー名に依存せず、既存設定を保持したままBridgeを再登録・起動します。通常利用PCは管理フォルダーへ移動する必要がなく、一般利用者のPCにはBridge自体が不要です。Git cloneした開発・管理PCでプロジェクト内のCMDを使う場合は、ユーザー名を含む絶対パスではなく、エクスプローラーで`（クローン先）\fleet-board\nfc-bridge`の順に開きます。このフォルダー内にインストール・再接続・アンインストール用CMDがあります。

ブラウザーからWindowsアプリを起動するカスタムURL機能は使用しません。BridgeはUSB機器を接続するPCごとに必要です。別PCではFleetFlow画面からセットアップツールを一度実行すると、そのPC専用のBridgeが登録されます。アンインストールは接続ガイドに表示されるPC共通コマンドから行います。接続確認は[http://127.0.0.1:17831/health](http://127.0.0.1:17831/health)を開き、NFCは`readerConnected`、QRは`qrReaderConnected`が`true`になることを確認します。起動履歴は`%LOCALAPPDATA%\FleetFlow\NfcBridge\nfc-bridge-launch.log`へ記録します。詳細は[nfc-bridge/README.md](nfc-bridge/README.md)を参照してください。

LAN上のFleetFlowを使うPCでは、そのURLを許可Originに加えてインストールします。

```powershell
powershell -ExecutionPolicy Bypass -File .\nfc-bridge\install.ps1 `
  -AllowedOrigins "http://192.168.1.20:3035;http://localhost:3035" `
  -QrComPort COM3
```

許可Originは完全一致で判定し、NFC Bridgeの起動時にだけ読み込みます。URLを変えた場合（サーバーのIP変更など）は、新しいURLを指定して再インストールしてください。LAN上の画面から初めて読み取るとき、ChromeやEdgeが「このデバイス上の他のアプリやサービスへのアクセス」の許可を求める場合があります。「許可」を選んでください。

NFC・QRの連携ソフトやリーダーが停止しても、FleetFlow本体は社員・車両の手動選択で継続利用できます。

## セキュリティ

設定（社員・車両・駐車区画・データ保存・復元）と操作履歴は、PINなしで開けます。LANへ接続できる人なら誰でも設定変更やNFC UIDの閲覧・変更、データ復元ができる前提です。全データの復元だけは、確認欄へ`RESTORE`と入力した場合に限り実行します。

本番は非rootユーザー、読み取り専用ファイルシステム、Linux capability全削除で実行します。DBポートはWindowsへ公開せず、アプリにはCSPなどのセキュリティヘッダーを設定しています。

## バックアップと復元

`db-backup`コンテナーが起動時と24時間ごとにバックアップを作成し、一時DBへ復元して検査します。30日を超えたバックアップは削除します。最終成功日時は「履歴」画面で確認できます。

手動バックアップ：

```powershell
# 開発DB
powershell -ExecutionPolicy Bypass -File .\scripts\database\Backup-Now.ps1

# 本番DB
powershell -ExecutionPolicy Bypass -File .\scripts\database\Backup-Now.ps1 -Production
```

復元できるかを検証：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\database\Verify-Backup.ps1 -Production
```

本番DBを実際に復元：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\database\Restore-Backup.ps1 `
  -Production -FileName fleet-YYYYMMDD-HHMMSS.sql.gz
```

実DBの復元は現在の内容を置き換えるため、ファイル名指定と`RESTORE`の確認入力が必要です。

PC故障に備える場合は`FleetFlow Production Backup Setup.cmd`を実行し、NAS、USB、OneDriveなどの同期フォルダーへ毎日複製してください。複製にはSHA-256検証が付き、保存先では新しい30ファイルを保持します。

### 新しいPCへ本番データを移す

古いPCで次を実行し、USBやNASなどを保存先に指定します。

```powershell
& '.\FleetFlow Production Migration Export.cmd'
```

新しいPCではリポジトリをcloneし、`FleetFlow Production Start.cmd`を一度実行してから次を実行します。

```powershell
& '.\FleetFlow Production Migration Import.cmd'
```

移行パッケージにはDBバックアップ、SHA-256、作成日時、Gitコミットを保存します。DBパスワードは移さず、新PC側で安全に再生成します。取込時は破損検査と復元検証を行い、最後に`RESTORE`と入力した場合だけ本番DBを置き換えます。

## 社内LANで本番公開する場合

初期設定では安全のため`127.0.0.1`だけへ公開され、同じPCからしか接続できません。LAN公開時は次をすべて実施してください。

1. サーバーPCのLAN IPを固定します。ルーターのDHCP予約（サーバーPCのMACアドレスへ同じIPを割り当てる）を推奨します。ルーターを操作できない場合はWindows側で固定IPを設定します。
2. `FleetFlow Production Start.cmd`を一度実行して本番設定を作成します。
3. `FleetFlow LAN Setup.cmd`をダブルクリックします。自動検出した固定LAN IPをアプリへ設定し、管理者権限の確認後、TCP 3035を同じ社内サブネットからだけ許可します。
4. 表示された`http://LAN-IP:3035`を別PCで開きます。
5. インターネットと来客用Wi-Fiから到達できないことを別端末で確認します。
6. 可能なら社内証明書とリバースプロキシでHTTPS化します。
7. 信頼するリバースプロキシが転送ヘッダーを上書きする場合だけ`FLEETFLOW_TRUST_PROXY=true`にします。直接公開は`false`のままにします。
8. NFCを使う各PCへNFC Bridgeを入れ、LAN用Originを許可します。
9. バックアップはBitLocker対応ドライブまたは権限制御済みNASへ複製します。
10. `FleetFlow Production Autostart Setup.cmd`を実行し、再起動後にサインインするとLANから開けることを確認します。

LAN IPを自動検出できない場合は、PowerShellで明示できます。

```powershell
& '.\FleetFlow LAN Setup.cmd' -Address 192.168.1.20
```

この設定はアプリの公開ポートだけを変更します。PostgreSQLのポートはLANへ公開されません。ブラウザーとAPIは同じURLを使用するため、FleetFlow本体にCORSの追加設定は不要です。

LAN IPへ公開した後も、サーバーPC自身からは`http://localhost:3035`で開けます（`127.0.0.1`へは常に公開します）。この併用公開と重なるため、公開アドレスに`0.0.0.0`は使えません（本番の事前診断でエラーになります）。

開発環境をLAN公開する場合は、同じコマンドに`-Development`を付けます。本番の`.env.production`ではなく、開発用の`.env`に`FLEETFLOW_DEV_BIND_ADDRESS`を保存します。稼働中ならアプリだけを再作成し、停止中なら次回の`FleetFlow Start.cmd`で反映します。

```powershell
& '.\FleetFlow LAN Setup.cmd' -Development -Address 192.168.1.20
```

開発・本番ともに起動確認とブラウザー表示先は設定したLAN IPを使います。Windowsファイアウォール規則はプライベート／ドメインネットワーク用です。パブリックネットワークでは許可されません。サーバーのネットワークがパブリックと判定されている場合、LAN設定コマンドの完了画面と本番の事前診断で警告するので、Windowsの設定 > ネットワークとインターネット > 該当アダプター > ネットワーク プロファイルの種類 を「プライベート」にしてください。LAN設定コマンド自体はPCの固定IP設定を変更しないため、固定IPまたはDHCP予約は別途設定してください。

開発環境ではNext.jsの`allowedDevOrigins`にも設定したLAN IPとサーバーのPC名を反映するため（`http://PC名:3035`でも開けます）、画面のJavaScript・フォント・開発時の自動更新がOrigin判定で拒否されません。公開先を変更した後はコンテナーの再作成が必要です（LAN設定コマンドは稼働中のアプリを自動再作成します）。PC名はWindowsの`COMPUTERNAME`（15文字までに切り詰められた名前）から自動設定されます。WSLから起動した場合は設定されず、PC名を変更した後はコンテナーの再作成が必要です。名前解決が環境に左右されるため、他のPCからはIPアドレスで開くことを推奨します。本番環境は`allowedDevOrigins`を使わず、アプリ自身が「画面のURLとAPIの接続先が同じか」を確認するため、IPでもPC名でも追加設定は不要です。

### 利用PCで確認すること

1. サーバー以外のPCのChromeまたはEdgeで`http://LAN-IP:3035`を開きます。
2. NFCを使うPCでは、社員証または車両タグを読み取れることを確認します。
3. 初回のNFC読取時に「このデバイス上の他のアプリやサービスへのアクセス」の許可を求められた場合は「許可」を選びます（LAN上の画面から同じPCのNFC Bridgeへ接続するため）。拒否した場合はアドレスバー左のサイト設定から許可へ戻せます。

### サーバーのIPが変わった場合

IPが変わると、古いIPを前提にした設定が次のように影響します。

| 古いIPが残る場所 | 起きること |
| --- | --- |
| `.env.production`の`FLEETFLOW_BIND_ADDRESS` | PCに無いIPへは公開できないため、アプリ全体が起動しません（サーバー自身のlocalhostからも開けません）。自動起動は公開アドレスを最大5分待ってからエラーを表示します |
| Windowsファイアウォール規則 | アプリが起動しても他のPCから接続できません |
| 利用PCのブックマーク | 古いURLを開いて接続できません |
| 利用PCのNFC Bridgeの許可Origin | 画面は開けますが、NFC読取だけが失敗します |

対応手順：

1. サーバーPCで`FleetFlow LAN Setup.cmd`をダブルクリックします。新しいIPを自動検出し、`.env.production`とファイアウォール規則（同じ名前の規則を置き換え）を更新します。アプリが稼働中なら自動で再作成します。停止中の場合は続けて`FleetFlow Production Start.cmd`を実行します。IPを自動検出できない場合は`-Address`で指定します。

   ```powershell
   & '.\FleetFlow LAN Setup.cmd' -Address 192.168.1.30
   ```

   開発環境も使っている場合は、同じコマンドに`-Development`を付けて開発用の`.env`も更新します。

2. 利用PCのブックマークを新しいURL（`http://新しいIP:3035`）へ変更します。
3. NFCを使う利用PCでは、新しいURLを許可Originにしてインストールし直します。NFC Bridgeは起動時にだけ設定を読むため、再インストールで再起動させます。

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\nfc-bridge\install.ps1 `
     -AllowedOrigins "http://192.168.1.30:3035;http://localhost:3035"
   ```

4. 利用PCで画面表示とNFC読取を確認します（上記「利用PCで確認すること」）。

自動起動の設定は毎回`.env.production`を読み直すため、登録し直す必要はありません。IPが変わらないよう、サーバーPCはDHCP予約か固定IPで運用してください。

利用・返却も設定も、ログインを要求しない共用端末向け設計です。LANへ接続できる人は業務データと設定を閲覧・操作できる前提なので、利用者ごとの権限管理が必要な環境では個別認証の追加が必要です。インターネットへ直接公開しないでください。


### 依存関係の監査方針

2026年10月23日時点でNext.jsは`16.4.2`です（16.4.0のセキュリティアドバイザリに対応）。Prisma CLI 7.10.0が固定する推移依存も含め、既知の脆弱性を避けるため`package.json`の`overrides`で次を固定しています。

- `deepmerge-ts` 8.0.2
- `mysql2` 3.24.5
- `source-map-js` 1.2.2

現在の`npm audit`は開発依存を含めて0件です。`npm audit fix --force`は互換性を壊す更新を含む可能性があるため使用しません。依存関係や`overrides`を変更した場合は、Docker内で監査、Prisma Client生成、本番ビルド、DB移行、統合テストを確認してください。

## トラブル対応

### 画面が開かない

```powershell
docker compose ps
docker compose logs --tail 100 app
docker compose restart app
```

本番の場合は、先に`FleetFlow Production Status.cmd`と`FleetFlow Production Health Check.cmd`を実行してください。サーバー自身のlocalhostでも開けない場合は、`FleetFlow Production Preflight.cmd`で公開アドレスがこのPCに割り当てられているか確認します（IPが変わった場合は「サーバーのIPが変わった場合」を参照）。

### 他のPCから開けない

サーバー自身では開けるのに他のPCから開けない場合は、次を順に確認します。

- サーバーのネットワークが「パブリック」になっていないか（`FleetFlow Production Preflight.cmd`で警告されます。プライベートへ変更します）。
- 利用PCがサーバーと同じサブネットにいるか。ファイアウォール規則は同じサブネットからだけ許可します（来客用Wi-FiやVPN経由では開けません）。
- 利用PCのブラウザーにプロキシが設定されている場合、ローカルアドレスがプロキシの例外になっているか。
- Windowsファイアウォール以外のセキュリティソフトがTCP 3035を遮断していないか。
- サーバーPCがスリープしていないか。サーバーPCは電源設定でスリープしないようにしてください。
- 利用PCで`http://サーバーIP:3035`ではなく`https://`や別のポートを開いていないか。

### 起動用cmdが動かない

- Docker Desktopの初期設定が完了しているか確認します。
- ファイル一式が同じプロジェクトフォルダーにあることを確認します。
- PowerShellからは`& '.\FleetFlow Production Start.cmd'`のように実行します。
- 詳細は`nfc-bridge/fleetflow-start.log`を確認します。サインイン時の自動起動の経過は`Autostart:`で始まる行に記録されます。

### NFC・QR連携ソフトに接続できないと表示される

連携ソフトや読取機器につながらないときは、画面右上のシステム状態から「詳細確認・管理を開く」を押し、「設定 → NFC・QR」へ進みます。Bridgeが動いている場合は画面の「NFC・QRを再接続」で機器を認識し直せます。Bridge自体へ接続できない場合は、同じ画面からセットアップ・修復ツールをダウンロードして実行します。

1. RC-S300／RC-S380またはQK30-Uを接続し直し、数秒待ちます（通常は自動再接続します）。
2. 戻らない場合は「設定 → NFC・QR」で「NFC・QRを再接続」を押します。
3. [NFC Bridgeのヘルス画面](http://127.0.0.1:17831/health)を確認します。NFCは`readerConnected`、QRは`qrReaderConnected`が`true`なら接続済みです。
4. Bridgeのヘルス画面を開けない場合は、接続ガイドの「セットアップ・修復ツール」をダウンロードして実行します。既存設定を保持したままBridgeが再登録・起動されます。
5. ヘルス画面は正常なのにLAN上の画面でだけ読めない場合は、開いているURLがBridgeの許可Originに含まれているか、ブラウザーでローカルネットワークへのアクセスを拒否していないかを確認します。
6. 復旧するまでは社員・車両を手動選択します。

画面の「診断を保存」は廃止しています。通常の接続確認はシステム状態とヘルス画面で行い、管理者が障害情報を保存するときは`FleetFlow Production Diagnostics.cmd`を実行します。

### データ更新が競合した

別の端末で先に変更されています。最新状態を読み直し、内容を確認してからもう一度操作してください。

### 履歴を絞り込み・保存したい

「履歴 → 車両利用履歴」で対象車両をクリックすると、過去1か月の利用履歴を表示します。各利用者の記録に「返却時のガソリン残量」を表示します。返却時に保存した残量（E・1/4・1/2・3/4・F）を使用し、未入力の記録は「未記録」、利用中は「未返却」と表示します。現在の車両残量から過去の残量を推測しません。「過去3か月」「期間指定」に切り替えられ、「車両一覧へ戻る」で車両を選び直せます。最初の車両一覧では利用記録を表示しません。車両名・車両番号・ナンバーで車両を検索できます。利用者名・開始日時・終了日時（日本時間）を指定すると、実際の利用開始から返却までが指定した時間帯に重なる記録を確認できます。日をまたぐ利用、現在利用中の車両、利用停止した車両の過去の記録も対象です。予約・取消は含みません。新しい利用では、利用開始時点の社員名・社員番号・所属・車両名・車両番号・ナンバーを保存し、登録情報を変更しても過去の表示を保持します。予約段階では固定せず、実際の利用開始時に保存します。導入前の履歴や旧バックアップは当時の情報を推測せず、現在の情報と「当時の登録情報未保存」の案内を表示します。開始時点の情報は開始時刻の訂正や返却取消でも変更しません。

「履歴」画面では、利用者・内容のキーワード、操作種別、開始日、終了日で絞り込めます。「CSV」を押すと現在の検索条件に一致する履歴を最大10,000件まで保存します。同じ画面でアプリ、DB、NFC、バックアップの状態と、アプリ・DBバージョンを確認できます。

### 本番障害の情報を保存したい

`FleetFlow Production Diagnostics.cmd`を実行します。コンテナー状態、アプリ、NFC、ディスク、直近ログを`diagnostics`フォルダーのZIPへ保存します。`.env.production`やDBパスワードは含みません。

## 補足

- `.env.production`、DBデータ、バックアップ、診断ZIPはGitへ登録しません。
- 本番バックアップは`backups/production`、開発バックアップは`backups`へ保存します。
- 更新前や異常を感じたときは`FleetFlow Production Health Check.cmd`を実行してください。
- 「異常」は起動・更新を止める項目、「注意」は外部バックアップ未設定、空き容量不足、再起動回数増加など早めの確認が必要な項目です。
